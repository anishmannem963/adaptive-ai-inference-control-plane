SYSTEM ARCHITECTURE

From browser policy to observable execution

The public sandbox uses the same interfaces as local Ollama, guarded Bedrock, Kubernetes, and future GPU targets.

  1. 01Netlify dashboardBuild request and constraints
  2. 02FastAPI gatewayValidate and admit traffic
  3. 03Policy routerFilter, normalize, and rank
  4. 04Reliability layerDeadline, circuit, bulkhead
  5. 05Provider adapterExecute or safely fall back
01

Policy gates first

Model, allowlist, outage, privacy, health, latency, cost, and quality constraints remove unsafe candidates before scoring.

02

Score eligible targets

Adaptive routing balances normalized cost, latency, utilization, and quality signals with request-controlled weights.

03

Contain failures

Deadlines, token buckets, bulkheads, circuit breakers, and bounded fallback stop one provider from consuming the gateway.

04

Avoid duplicate spend

Exact caching and Redis-backed idempotency prevent repeated requests from unnecessarily executing a provider.

05

Recover visibly

Half-open single-flight probes restore isolated providers while health, attempts, fallbacks, and traces remain inspectable.

06

Deploy reproducibly

Docker, kind, Kubernetes, Helm, Terraform, CI, and release artifacts make the same control plane portable.

CLAIM BOUNDARY

Not presented as production proof

  • Public provider responses are simulated
  • Azure and GCP adapters are not implemented
  • Bedrock has not run the paid validation gate
  • vLLM GPU serving remains planned
  • Kafka is excluded without a justified workload
